## Формат 1. Учебник — Markdown, по одному файлу на тему

Имя файла: `lecture-t01.md`, `lecture-t02.md`, … `lecture-t15.md`. Если для тестов не хватает ни одной из 15 тем (например, история философии по эпохам и персоналиям), добавь свои темы `t16`, `t17`… и назови их в плане.

Правила:
- Заголовок темы: `# Тема 1. Истоки культуры мышления {#t1}`
- Подраздел: `## 1.2 Философия и другие формы мировоззрения {#t1-2}` (можно `###` с id `{#t1-2-3}`).
- **Перед каждым блоком текста — отдельная строка с его id**: `{#t1-2-p3}` (тема 1, подраздел 2, блок 3). Блок — это абзац, список или выделенная врезка. Id уникальны во всём учебнике и больше не меняются.
- **Блок — максимум ~90 слов и понятен сам по себе** (его покажут отдельной карточкой под тестом). Длинную мысль дели на несколько блоков.
- Сразу под заголовком темы — блок «коротко» (2–3 предложения сути темы).
- В конце каждой темы — подраздел `## Шпаргалка {#tN-cs}`: 10–20 самых важных фактов списком (каждый пункт — отдельный блок со своим id не нужен, весь список — один блок `{#tN-cs-p1}`).
- Разрешено: абзацы, списки `- `, **жирный** для терминов и имён, таблицы Markdown (для сравнения школ, эпох), и три вида врезок — строкой, начинающейся так:
  - `> 💡 Запомни: …` — главное определение или факт;
  - `> ⚠️ Ловушка: …` — где в тестах путают (похожие термины, имена, даты);
  - `> 👤 …` — персоналия: **Имя** (годы, страна) — главная идея, произведение.
- Нельзя: HTML, картинки, ссылки на внешние сайты, сноски.

Пример:

```markdown
# Тема 1. Истоки культуры мышления {#t1}

{#t1-p0}
Коротко: философия выросла из мифа и религии, когда люди стали объяснять мир разумом и доказательствами. Её главный вопрос — отношение мышления к бытию.

## 1.2 Философия и другие формы мировоззрения {#t1-2}

{#t1-2-p1}
**Мировоззрение** — система обобщённых взглядов человека на мир и своё место в нём. Это шире, чем наука: в мировоззрение входят знания, ценности, убеждения и идеалы.

{#t1-2-p2}
> ⚠️ Ловушка: «система обобщённых взглядов на действительность» — это мировоззрение, а не философия. Философия — лишь одна из форм мировоззрения, его теоретическое ядро.
```

## Формат 2. Разбор 500 вопросов — JSONL (одна строка = один вопрос)

Имя файла: `q-001-025.jsonl`, `q-026-050.jsonl`, … (по 25 вопросов). Каждая строка — один JSON-объект **в одну строку**:

```json
{"n":1,"q":"Система обобщенных взглядов на окружающую действительность","topic":"t1","key":"Мировоззрение — система обобщённых взглядов на мир и место человека в нём.","why":"Именно так определяется мировоззрение: оно объединяет знания, ценности и убеждения. Философия — лишь его теоретическая форма, поэтому она не подходит как ответ.","wrong":{"наука":"Наука — систематическое доказательное знание о закономерностях мира, это часть мировоззрения, а не оно целиком.","философия":"Философия — теоретическое ядро мировоззрения, а не вся система взглядов.","культура":"Культура — всё созданное человеком (материальное и духовное), понятие шире мировоззрения.","искусство":"Искусство — образное освоение мира, одна из форм культуры."},"lec":["t1-2-p1","t1-2-p2"],"check":""}
```

Поля:
- `n` — номер вопроса в файле (1…500), по порядку, без пропусков.
- `q` — первые 6–10 слов вопроса **дословно** (по ним программа сверяет номер).
- `topic` — id темы (`t1`…).
- `key` — одна фраза «запомни» (жирным на карточке).
- `why` — 2–4 предложения: почему правильный (первый) вариант верен. Простыми словами, без воды.
- `wrong` — для **каждого** из 4 неверных вариантов: ключ — текст варианта **дословно**, значение — 1 предложение, почему не подходит или что это понятие означает на самом деле.
- `lec` — 1–3 id блоков учебника, где объяснён ответ. **Эти id обязаны существовать** в уже написанном учебнике.
- `check` — пусто `""`. Если ключ в файле, по-твоему, спорный или ошибочный — **не меняй ответ** (на экзамене засчитают первый вариант), а коротко объясни сомнение здесь.

Правила для JSON: внутри текста **не используй прямые двойные кавычки `"`** — только «ёлочки»; никаких переносов строк внутри строки; каждая строка — валидный JSON.

## Формат 3. Дополнительные тесты — JSONL

Имя файла: `x-t01.jsonl` … (по теме). Строка:

```json
{"id":"x-t1-01","topic":"t1","q":"Кто впервые употребил слово «философия»?","opts":["Пифагор","Сократ","Платон","Аристотель","Фалес"],"key":"Слово «философия» ввёл Пифагор (VI в. до н. э.).","why":"…","wrong":{"Сократ":"…","Платон":"…","Аристотель":"…","Фалес":"…"},"lec":["t1-1-p1"]}
```

Правильный ответ — **первый** в `opts`; всего 5 вариантов; неверные — правдоподобные (реальные понятия и имена из курса). Вопросы разного типа: определения, «кто автор», «к какой школе относится», «что общего / в чём разница», «что из перечисленного не относится». Каждый `lec` — существующий id.

## Как работать (по шагам; после каждого шага жди моё «дальше»)

**Шаг 0 — план (без файлов).** Прочитай всё. Дай:
1. список тем с id и подразделами (`t1`…`t15` и твои добавленные, если нужны);
2. для каждой темы — номера тестов, которые к ней относятся (диапазонами), и проверку, что всего 500;
3. список «дыр»: тесты, ответа на которые нет в лекциях, и куда ты добавишь материал.

**Шаг 1 — учебник.** По одной теме в сообщении: `lecture-t01.md`, затем `lecture-t02.md`, … Учитывай распределение тестов из плана: всё, что нужно для «своих» тестов темы, должно быть в её тексте.

**Шаг 2 — разбор 500 тестов.** По 25 вопросов в сообщении (`q-001-025.jsonl`, …). Ссылайся только на уже написанные блоки. Если для ответа блока не хватает — в начале сообщения дай добавку к учебнику в таком виде, и потом ссылайся на неё:

```markdown
@после t3-2-p4
{#t3-2-p4a}
Текст нового блока…
```

**Шаг 3 — дополнительные тесты.** По 1–2 темы в сообщении (`x-t01.jsonl`, …).

**Шаг 4 — проверка.** Отчёт: какие номера 1…500 пропущены; какие `lec` указывают на несуществующие id; все `check` с сомнениями списком; темы, где мало блоков для тестов.

Если ты умеешь создавать файлы — создавай настоящие файлы с этими именами (в конце дополнительно сложи всё в три файла: `lecture.md`, `questions.jsonl`, `extra.jsonl`). Если не умеешь — выдавай каждый файл одним блоком кода с именем файла над ним.

В конце **каждого** сообщения — одна строка прогресса: `Готово: … · Дальше: …`.

## Качество (важно)

- Точность важнее красоты: имена, годы, названия произведений и школ — без выдумок. Если не уверен — не пиши или отметь в `check`.
- Пиши на русском, простыми короткими предложениями, как хороший преподаватель объясняет первокурснику. Термины — **жирным** при первом появлении.
- Казахстанский контекст (тема 15 и где уместно): аль-Фараби, Ходжа Ахмед Яссауи, Жусуп Баласагуни, Махмуд Кашгари, Асан Кайгы, Абай, Шокан Уалиханов, Ыбырай Алтынсарин, Шакарим и др. — только проверенные факты.
- Не пересказывай тесты в учебнике и не пиши «в тесте спрашивают…». Учебник — самостоятельный текст.
- Пояснения в `why`/`wrong` не должны противоречить учебнику.
- Сохраняй одинаковое написание имён и терминов во всех файлах.
