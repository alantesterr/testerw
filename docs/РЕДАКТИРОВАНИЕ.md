# Как устроен код и что где менять

Сайт написан на чистом HTML, CSS и JavaScript — без сборки и фреймворков.
Всё работает прямо в браузере. Один глобальный объект `SP` (StudyPlay)
связывает модули между собой.

## Порядок загрузки (в `index.html`)

1. `js/config.js` — настройки автора (ссылки на сайты вуза).
2. `js/core/*` — ядро: `util` (помощники), `icons` (иконки), `store` (хранилище),
   `i18n` (переводы), `settings` (тема/язык/шрифт), `ui` (окна, меню, уведомления),
   `shell` (каркас и навигация).
3. `js/i18n/ru.js`, `kk.js`, `en.js` — словари.
4. `js/services/*` — `api` (группы), `auth` (профиль), `data` (импорт оценок).
5. `js/features/*` — разделы сайта и общий движок тестов.
6. `js/app.js` — запуск.

Если добавляете новый файл — не забудьте подключить его в `index.html`
в правильном месте (разделы — после ядра и сервисов).

## Частые задачи

### Поменять цвет, отступ, радиус, размер шрифта

Всё в одном файле: **`css/tokens.css`**. Там переменные для светлой и тёмной
темы. Поменяли переменную — изменилось на всём сайте. Например, основной цвет:
`--accent`. Цвета занятий в расписании: `--k-lecture`, `--k-practice` и т.д.

### Поменять или добавить текст (перевод)

Тексты не вшиты в код — они в словарях `js/i18n/`. Один ключ = одна строка.

1. Найдите ключ (например, `nav.schedule`) в `js/i18n/ru.js` и поменяйте значение.
2. То же самое в `kk.js` и `en.js` (если строки нет — покажется русская).
3. В коде текст берётся так: `SP.t('nav.schedule')`, а в HTML — атрибутом
   `data-i18n="nav.schedule"`.

Для чисел есть формы: `{ one: '{n} вопрос', few: '{n} вопроса', many: '{n} вопросов' }`
и вызов `SP.t('tester.qCount', { n: 5 })`.

### Добавить иконку

Иконки — из набора [Lucide](https://lucide.dev), лежат в `js/core/icons.js`.
Найдите нужную на lucide.dev, скопируйте внутренность тега `<svg>` и добавьте
строкой в объект `P` в `icons.js`. Используется как `SP.icon('имя')`.
Эмодзи не используем — только SVG-иконки.

### Поправить разбор журнала оценок (Platonus)

Файл **`js/features/grades.js`**, функция `normalize()`. Platonus может отдавать
журнал в разном виде, поэтому разбор «гибкий»: он ищет названия предметов
(`NAME_KEYS`) и показатели (`METRIC` — current, rk1, rk2, admission, exam, total,
letter). Если какое-то поле не распозналось — добавьте его название в нужный
регулярное выражение в `METRIC` или `NAME_KEYS`.

Чтобы увидеть, что именно пришло: в разделе «Оценки» → «Исходные данные».

### Поправить разбор расписания (Timetable / сохранённая страница)

Файл **`js/features/hub.js`**, функция `parseScheduleHtml()`. Она ищет в HTML
таблицу с днями недели (на русском, казахском или английском) и собирает занятия.
Если Timetable изменит вёрстку — правьте здесь.

### Добавить новый раздел (вкладку)

1. Создайте `js/features/моё.js` по образцу любого раздела. Зарегистрируйте его:
   `SP.views.register('myid', { titleKey:'nav.my', mount, show, refresh })`.
2. Добавьте пункт в массив `MAIN` в `js/core/shell.js` (иконка + ключ перевода).
3. Добавьте строки перевода (`nav.my`, `nav.myShort`) в три словаря.
4. Подключите файл в `index.html`.

## Полезно знать

- **Состояния кнопок** уже заложены в классах `.btn`, `.btn-primary`,
  `.btn-danger` и т.д. (`css/components.css`): hover, active, focus, disabled,
  загрузка. Опасные действия — `.btn-danger` (красные).
- **Хранилище**: `SP.store.get/set` — мелкие данные (localStorage),
  `SP.idb('имя')` — крупные файлы (IndexedDB). Всё в try/catch: если браузер
  запрещает — сайт просто работает без сохранения.
- **Движок тестов** общий для Тестера, Дизайнера, Плеера и папок —
  `js/features/test-engine.js` (разбор, проверка, экспорт) и `quiz.js`
  (прохождение). Банк вопросов — `bank.js`.
- Проверяйте изменения на светлой и тёмной теме, на трёх языках и на узком
  экране (примерно 360 px).
